# TTS Content Studio

A self-hosted text-to-speech studio for content creators — generate narration
audio from text, manage projects, and queue conversion jobs. Runs **100% on
CPU**: no GPU and no per-character API costs.

Speech is generated by [Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M)
(Apache-2.0) running on ONNX Runtime via
[kokoro-onnx](https://github.com/thewh1teagle/kokoro-onnx).

## Features

- 11 natural voices (American & British English)
- Editor with instant audio preview (first 500 chars)
- Saved projects (name, text, voice, speed)
- Background job queue with retry
- Downloadable WAV output
- REST API with interactive docs at `/docs`
- Single-command Docker deployment
- Portuguese (pt-BR) user interface

## Tech Stack

**Backend:** Python 3.11+ · FastAPI · SQLAlchemy (async) · SQLite · ONNX Runtime
**Frontend:** React 18 · TypeScript · Vite · Tailwind CSS · shadcn/ui

## System Requirements

- 4+ CPU cores
- 4 GB RAM (model is a 325 MB fp32 ONNX; ~500 MB RSS during synthesis)
- `espeak-ng` (phonemizer backend used by kokoro-onnx)
- Git LFS (for the model files)

## Quick Start

```bash
git clone https://github.com/vsousadelvek/DelkokoTTs.git
cd DelkokoTTs
git lfs pull   # fetches kokoro-v1.0.onnx (325 MB) + voices-v1.0.bin (27 MB)
```

### Backend

```bash
cd backend

# System dependency (phonemizer)
sudo apt-get install espeak-ng        # Debian/Ubuntu
# brew install espeak-ng              # macOS

python -m venv .venv
source .venv/bin/activate             # Windows: .venv\Scripts\activate
pip install -r requirements.txt

uvicorn app.main:app --host 0.0.0.0 --port 8000
```

API docs: http://localhost:8000/docs

### Frontend (development)

```bash
cd frontend
npm install
npm run dev
```

App: http://localhost:5173 (Vite proxies `/api` to port 8000)

### Docker (single container, production)

```bash
docker compose up -d --build
```

Then open http://localhost:8000 — the backend serves the built frontend
directly, so no separate web server is needed. To rebuild the image without
downloading the model files at build time, they are fetched from the pinned
upstream release (see `scripts/download_models.sh`).

## API Overview

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/health` | Health check (engine status, voice count) |
| GET | `/api/stats` | Project/job/engine stats |
| GET | `/api/tts/voices` | List voices |
| POST | `/api/tts/synthesize` | Generate audio (`text`, `voice`, `speed`) → `{audio_url, duration}` |
| POST | `/api/tts/preview` | Same, limited to the first 500 chars |
| GET | `/api/tts/audio/{file}` | Download generated WAV |
| GET/POST/PUT/DELETE | `/api/projects/` | Project CRUD |
| GET/POST/DELETE | `/api/jobs/` | Background synthesis jobs (+ `POST /{id}/retry`) |

## Repository Layout

```
backend/            FastAPI app
  app/core/         config + TTS engine wrapper (kokoro-onnx)
  app/api/routes/   tts / projects / jobs routers
  app/models/       SQLAlchemy models + session
  storage/models/   ONNX model + voice styles (Git LFS)
  storage/audio/    generated WAV output (gitignored)
  tests/            API tests
frontend/           React + Vite app (src/pages, src/components/ui)
docs/               system architecture + TTS research notes
scripts/            model download script (Docker/CI)
```

## Notes & Limitations

- Output format is WAV. MP3 export is on the roadmap.
- The job queue uses FastAPI `BackgroundTasks`: it is in-process and does not
  survive restarts. For heavier use, point `process_job` at a real queue.
- No authentication — run it behind a reverse proxy with auth (or on a private
  network) if exposed to the internet.
- `docs/ARQUITETURA_TTS_CPU.txt` is a research blueprint exploring a custom
  distilled TTS model (StyleTTS 2-style decoder + Wavehax vocoder). It is
  documentation of the design study, not implemented code.
